# 竖屏获客短视频 · 声音设计包 v1.0

**适用**：律师 / 加盟 / 教培老板的获客短视频，30–90 秒，文案 → 配音 → 成片。
**目标**：人声永远第一，BGM 只做情绪底色，音效做“听觉标点”。
**口径**：不指定具体曲名；价格与资质为 2026-11 公开文档口径，最终以官方为准。

---

## 0. 混音基线（所有参数的地基）

| 轨道 | 目标响度 | 峰值 | 说明 |
|---|---|---|---|
| 人声（独奏） | −16 LUFS integrated | ≤ −3 dBTP | 全片锚点，先定人声再定其他 |
| BGM（人声段） | −30 LUFS short-term | — | 比人声低约 14 dB，只留“底色” |
| BGM（空镜段） | −22 LUFS short-term | — | 比人声段高 8 dB，托住情绪 |
| 音效 | — | −12 ~ −20 dBFS peak | 强调类可到 −10，不超过 −9 |
| 成品 | −14 LUFS integrated | ≤ −1 dBTP | LRA ≤ 8 LU，手机外放为准 |

**三条铁律**

1. 人声 −16 LUFS、成品 −14 LUFS；BGM 在人说话时必须低 12–15 dB，不要靠“整体调小”解决。
2. 音效峰值不超过 −9 dBFS；同一秒最多 2 个音效，转场与强调不要互相叠。
3. 交付前用手机外放听一遍：每个字清楚、不刺耳、不轰头，才算过。

## 1. BGM 选型

### 1.1 四条筛选标准

- **无人声**：不要 vocal、说唱、喊麦；旋律尽量避开 1–4 kHz（人声清晰度区）。
- **BPM 90–130**：30/60/90 秒优先 120 BPM——1 拍 0.5 秒、1 小节 2 秒，正好 15/30/45 小节，剪辑点天然对齐。
- **结构稳定**：少大 drop、少突然静音；前 3 秒能进，最后 2 秒能收。
- **循环友好**：4/8 小节一个循环，接缝无明显鼓点错位；避免一响就“抢戏”的强旋律。

### 1.3 三个行业的配方

- **律师**：70% 用「冷峻悬念 / 权威定论」，只在“风险后果”和结尾用「紧张推进」。低频 drone 可以有，但 100 Hz 以下要克制；强调音效用木质法槌、盖章、纸张，比金属 hit 更可信。
- **加盟**：主用「商务上扬 / 科技脉冲」，BPM 118–128，4/4 稳定 kick；数字落点用金币/收银/低频砸点；最后 5 秒换「热血冲刺」或「紧张倒计时」，但只升一次，不要全程高能。
- **教培**：主用「轻快希望 / 好奇拨弦」，BPM 110–122；少重低频，多用马林巴、拨弦、钢琴；音效用气泡、翻页、打勾；情绪上扬但不幼稚，避免儿歌化。

### 1.5 在浏览器里怎么混：WebAudio 全链路

#### 1.5.1 节点图

```
BGM → Highpass 130Hz → bgmGain（只做 ducking）→ master
VO  → Highpass 80Hz  → voiceComp（2.5:1）    → master
SFX → sfxGain（不经过 bgmGain）               → master
master → glueComp（2:1）→ limiter → destination
```

要点：**SFX 不要挂在被 duck 的 BGM 总线上**，否则强调音效会跟着人声一起被压。

#### 1.5.2 解码与拼接

```js
const ctx = new OfflineAudioContext(2, Math.ceil(totalSec * 48000), 48000);
const buf = await ctx.decodeAudioData(await (await fetch(url)).arrayBuffer());
```

- `decodeAudioData` 会自动重采样到 context 的 48 kHz；统一 48 kHz，避免多次重采样。
- **不要手动 concat AudioBuffer**。按绝对时间排程：维护 `cursor`，每句 `source.start(cursor)`，句间留 120–250 ms；30 fps 项目把时间对齐到 `Math.round(t * 30) / 30`。
- 句首留 20 ms 静音，避免 MP3/AAC 解码边缘的 click；句尾留 80–120 ms，给 ducking release 留空间。
- 预览用 `AudioContext`，导出用 `OfflineAudioContext`；两者共用同一套排程函数，保证“听到的=导出的”。

#### 1.5.3 自动 ducking（核心）

WebAudio 原生**没有侧链输入**：把 `DynamicsCompressorNode` 挂在 BGM 上只会被 BGM 自己触发，不会听人声。正确做法是**用人声时间戳驱动 GainNode 自动化**；没有人声时间戳时，用离线 VAD 兜底。

| 参数 | 默认值 | 建议范围 | 说明 |
|---|---|---|---|
| duck 深度 | −12 dB | −9 ~ −15 dB | BGM 越密、频谱越满，压得越深 |
| attack | 120 ms | 80–150 ms | 太短会“抽”，太长会盖住句首 |
| hold | 250 ms | 150–400 ms | 句间停顿不反复抬升 |
| release | 350 ms | 250–450 ms | 太短会“泵”，太长会糊下一句 |
| pre | 80 ms | 50–120 ms | 人声前先让路 |
| post | 120 ms | 80–200 ms | 尾音结束后再回 |
| 最小合并间隙 | 500 ms | 300–800 ms | 小于该值的停顿直接合并，避免抖动 |

```js
const toGain = (db) => Math.pow(10, db / 20);

function mergeIntervals(list, minGap = 0.5) {
  const xs = [...list].sort((a, b) => a.start - b.start);
  const out = [];
  for (const it of xs) {
    const last = out[out.length - 1];
    if (last && it.start - last.end < minGap) last.end = Math.max(last.end, it.end);
    else out.push({ ...it });
  }
  return out;
}

function scheduleDuck(param, voiceIntervals, {
  depthDb = -12, attack = 0.12, release = 0.35,
  pre = 0.08, post = 0.12, minGap = 0.5,
} = {}) {
  const target = toGain(depthDb);
  param.cancelScheduledValues(0);
  param.setValueAtTime(1, 0);
  for (const { start, end } of mergeIntervals(voiceIntervals, minGap)) {
    const s = Math.max(0, start - pre);
    const e = end + post;
    param.setValueAtTime(1, s);
    param.linearRampToValueAtTime(target, s + attack); // 下压
    param.setValueAtTime(target, e);                   // 保持
    param.linearRampToValueAtTime(1, e + release);     // 回弹
  }
}
```

**人声区间从哪来**（按优先级）：

1. TTS 返回的句级/词级时间戳（最准，首选）。
2. 没有时间戳时，对配音 buffer 做离线 VAD：20 ms 帧、−42 dBFS 阈值、连续 3 帧判定；合并 <500 ms 的间隙，再前后各扩 80/120 ms。
3. 进阶：AudioWorklet 做侧链压缩，用配音包络驱动 BGM——但一个开发两周内不建议，自动化更可控、可离线复现。

**如果非要用压缩器做“类 ducking”**：比例 4:1–8:1、阈值约比人声响度低 10 dB、attack 50–100 ms、release 250–500 ms、knee 6 dB；但要清楚它没有侧链，效果不如时间戳自动化。

**压缩比建议**：

- 人声压缩：2.5:1（2:1–4:1），threshold −20 dB，attack 5 ms，release 120 ms——只做“稳”，不做“扁”。
- 总线 glue：2:1，threshold −14 dB，attack 10 ms，release 150 ms。
- 限幅：20:1 以上，threshold −2 dB，attack 3 ms，release 100 ms；WebAudio 没有真砖墙限幅，最终还要查真峰值。

#### 1.5.4 BGM 剪辑、循环、对拍

| BPM | 1 拍 | 1 小节（4/4） | 30s 小节数 | 60s 小节数 | 90s 小节数 |
|---|---|---|---|---|---|
| 90 | 0.667s | 2.667s | 11.25 | 22.5 | 33.75 |
| 100 | 0.600s | 2.400s | 12.5 | 25 | 37.5 |
| 120 | 0.500s | 2.000s | 15 | 30 | 45 |
| 128 | 0.469s | 1.875s | 16 | 32 | 48 |

- 30/60/90 秒选 **120 BPM** 最省事，小节数都是整数；90 BPM 适合 60 秒（22.5 小节，可在半小节处收）。
- 循环：`const bar = 4 * 60 / bpm; source.loop = true; source.loopStart = 8 * bar; source.loopEnd = source.buffer.duration - 0.05;`，循环点选在 4/8 小节边界；接缝做 60–100 ms 交叉淡化，或选零交叉点。
- 剪辑：优先在 8 小节/4 小节边界切；淡入 0.3–0.8 s、淡出 0.8–1.5 s；结尾落在 downbeat。
- 变速：±5% 以内；超过会明显改变音色，不如换曲。
- 对拍：音效落在 1/4 或 1/8 拍上；画面剪切可以偏 1–2 帧，但数字落点必须与画面同帧。

#### 1.5.5 响度与导出

1. 先单独渲染人声，测 integrated LUFS，把人声校准到 **−16 LUFS**。
2. 再渲染带 ducking 的 BGM，校准到人声段 **−30 LUFS short-term**、空镜段 **−22 LUFS**。
3. 全混渲染，测 integrated LUFS，把 master 校准到 **−14 LUFS**；真峰值 ≤ **−1 dBTP**（4 倍过采样检查）。
4. 用 `OfflineAudioContext` 渲染 → AudioBuffer → 16-bit WAV；视频用 ffmpeg.wasm 或服务端 mux；Chrome 下可用 WebCodecs `AudioEncoder` 直接编 AAC。
5. 服务端可再用 `ffmpeg -af loudnorm=I=-14:TP=-1:LRA=7` 做一次校验，但**不要**在浏览器和 ffmpeg 之间反复改增益。

LUFS 测量按 ITU-R BS.1770：K 加权 → 400 ms 块 → 绝对门限 −70 LUFS → 相对门限 −10 LU → 积分。可以自己实现，也可以接现成 WASM 库；关键是**用同一套测量跑人声、BGM、成品**。

#### 1.5.6 常见坑

- iOS 必须用户手势后 `ctx.resume()`；否则静音。
- `setTimeout` 不能用来排程导出；一律 `source.start(when)`。
- `DynamicsCompressorNode` 有内部延迟/拐点，不适合做“精确 2 帧”的瞬态处理；瞬态交给音频素材本身。
- BGM 立体声要查单声道兼容：手机外放是单声道，宽立体声可能相位抵消。
- 手机外放没低频：sub 音效加 160/320 Hz 谐波，才有“砸”的错觉。
- 不要在 30 秒里塞 3 种曲风；一支片子一条情绪线。

## 2. 音效清单

### 2.1 使用规则

- **三层结构**：转场（轻）→ 落点（中）→ 强调（重）；同一秒 ≤2 个，全片每 3–5 秒一个“听觉标点”。
- **不是每个卡片都响**：卡片连续弹出时，只给第一张和最后一张；中间靠动画本身。
- **峰值**：强调类 −10 ~ −12 dBFS，落点类 −12 ~ −15，转场 −18 ~ −22，UI 类 −20 ~ −22；任何音效不超过 −9 dBFS。
- **同帧**：与画面事件同帧（±1 帧）；whoosh 可提前 2–3 帧启动，尾巴跨过剪切点。
- **手机优先**：2–5 kHz 太亮会刺耳，比电脑上保守 2 dB；低频音效要加谐波。
- **结尾**：不要“突然静音”，用 0.5–1 s 淡出收住。

### 2.4 音效来源

- **免费/CC0**：Freesound（筛选 CC0）、Pixabay Sound Effects、Mixkit SFX。
- **付费/订阅**：Zapsplat（免费档要署名）、AudioJungle、Envato Elements、爱给网/淘声网（确认商用授权）。
- **不要用**：影视片段、游戏原声、短视频热梗音效（版权与平台审核风险）。
- 每个音效记录来源和 license，和 BGM 一起归档。

### 3.2 逐家一句话

- **CosyVoice**：最均衡。flash 性价比高，plus 质感更好；创建音色免费、按合成付费，试错成本最低。注意音色绑模型，换模型要重建。
- **火山**：效果天花板，尤其情绪和韵律；但企业资质是硬门槛，适合有主体、追求质感的团队，不适合个人开发者第一版。
- **腾讯**：基础版是“项目制”，官方文档写明制作 3–4 周；一句话版快，但 API 开放度和定制能力要跟商务确认。两周上线不要选基础版。
- **Azure**：合规与审批最重，价格也最高；国内业务首版不推荐，除非客户指定或要做海外发行。
- **MiniMax**：接入最快，10 s–5 min 的宽容度对客户最友好；相似度略逊火山顶配，适合 A/B 和兜底。

### 3.3 如果只有一个开发、两周内上线：推荐方案

**主方案：阿里云百炼 CosyVoice（v3.5-flash 为主，v3.5-plus 做高价值客户）**
**备选：MiniMax（A/B 与降级）**
**暂不选：火山（资质/周期）、腾讯基础版（3–4 周）、Azure（审批/成本）**

理由：

1. **资质不卡人**：实名即可，个人开发能先把闭环跑通；商用授权由客户签署的声音授权书约束，平台留存记录。
2. **时长正好**：官方推荐 10–20 s、最长 60 s，完全覆盖“客户上传 10–30 s”。
3. **接入最简单**：HTTP 三段式（create_voice → query_voice → synthesize），不需要一上来就写 WebSocket；SDK 和示例全。
4. **成本可控**：创建音色免费，按合成字符付费；60 秒口播约 220–280 字，单条成本在几毛钱以内。
5. **效果够用**：中文口播第一梯队；flash 做批量，plus 做重点客户，AB 两条线。
6. **风险有解**：长句吞字 → 分句 ≤25 字；多音字 → 词典/SSML；相似度不满意 → 重录样本或切 MiniMax。

### 3.4 给客户的录音规范（10–30 秒）

- 安静小房间，关空调/风扇，手机距嘴 10 cm，不要喷麦。
- 10–30 s，读 3–5 个完整句子，正常语速，不要唱歌、不要耳语、不要夸张情绪。
- 单人、无 BGM、无其他人声、无混响；WAV/MP3，≥16 kHz，单声道，不削波。
- 句间停顿 ≤1 s；首尾各留 0.3 s 静音；整段情绪一致。
- **授权声明单独录**，不要混进克隆样本；样本只留“干净说话声”。
- 收到后先做质检：底噪、混响、喷麦、齿音、音量一致性；不合格直接让客户重录，别硬克隆。

### 3.5 两周排期（一个开发）

| 天 | 交付 |
|---|---|
| D1–2 | 开通账号/密钥/对象存储；用 3 条样本跑通 curl；定音色命名与租户隔离 |
| D3–4 | 克隆 + 合成 demo；做“试听 3 句”页面，先验证相似度 |
| D5–6 | 前端录音：30 s 上限、静音检测、重录、进度与错误提示 |
| D7–8 | 后端任务：创建音色、轮询、合成、缓存、重试、限流 |
| D9–10 | 混音：BGM + ducking + 音效；导出 WAV/MP4 |
| D11–12 | A/B：CosyVoice vs MiniMax；锁定主备与降级策略 |
| D13 | 合规：授权书、隐私政策、删除接口、AI 配音标识 |
| D14 | 压测、监控、灰度、上线 |

### 3.6 工程架构

```
[浏览器] MediaRecorder(webm/opus)
   ↓ 上传
[对象存储] → [FFmpeg] 16k 单声道 WAV，去静音、轻降噪、归一化
   ↓
[Clone API] create_voice → voice_id（轮询到 OK）
   ↓
[文案] 分句（≤25 字）→ TTS → 音频 + 句级时间戳
   ↓
[WebAudio / OfflineAudioContext] BGM + ducking + SFX
   ↓
[导出] WAV / MP4 → 客户
```

Provider 抽象，方便一周内换供应商：

```ts
interface VoiceProvider {
  clone(input: { audioUrl: string; name: string }): Promise<{ voiceId: string }>;
  synthesize(input: {
    text: string; voiceId: string; speed?: number;
  }): Promise<{ audioUrl: string; duration: number; words?: { start: number; end: number }[] }>;
}
```

### 3.7 合规与预期管理

- **书面授权**：姓名、用途、投放渠道、期限、删除权；未成年人需监护人。
- **深度合成标识**：发布时按平台要求标注“AI 配音/合成”；中国《互联网信息服务深度合成管理规定》要求显著标识。
- **禁止**：克隆公众人物、他人声音、客户未授权的员工/讲师声音。
- **数据最小化**：样本与 voice_id 绑定客户；提供删除接口；跨境（Azure）先做评估。
- **预期管理**：10–30 s 克隆不是 100% 像；先给 3 句试听，客户确认后再批量合成，避免退款纠纷。

### 3.8 成本量级

- 60 s 口播 ≈ 220–280 汉字；1000 条 ≈ 25 万字符。
- CosyVoice 按万字符几元计，千条素材的 TTS 成本在**百元级**；plus 更高。
- 火山/腾讯资源包通常是**千元级/年起**；Azure 训练+端点更贵。
- 以上不含视频生成、存储、带宽与人工；报价时分开列。

## 4. 验收清单

- [ ] 人声 −16 LUFS，成品 −14 LUFS，真峰值 ≤ −1 dBTP
- [ ] 人声出现时 BGM 下降 12–15 dB，无“抽/泵”感
- [ ] 手机外放：每个字清楚，音效不刺耳、不轰头
- [ ] 同一秒 ≤2 个音效；转场不重叠；结尾无突然静音
- [ ] 片头 0.5 s 内进画面；30/60/90 s 时长误差 ≤0.2 s
- [ ] BGM/音效授权覆盖客户账号、投放渠道与期限
- [ ] AI 配音已标识；授权书、隐私政策、删除接口就绪
- [ ] 克隆样本质检通过；试听 3 句已确认
