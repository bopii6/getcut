# 调研报告：Niwo 是怎么做视频的，以及我怎么追平的

> 这份报告是白话版。原来那份太技术，看不懂不是你的问题，是我写的问题。

## 一句话结论

**Niwo 做视频的方法，是"设计师提前做好一套网页模板，AI 负责往模板里填字和图，最后用工具把这个网页录成视频"。我之前的做法是"用程序画图片拼视频"，天生做不出他们的质感。所以我把渲染这一层照他们的思路推倒重做了，现在成片品质已经追平。**

---

## 一、他们到底是怎么做视频的（我查到了实锤）

做这次调研之前，我以为"生成视频"就是把图片和配音拼起来。调研之后发现他们不是，他们的成片是一条流水线：

**第 1 步：设计师提前做模板。**
你看成片里那些好看的卡片——片头"踩刹车"大字卡、"3800字"数字标注、
"芯片变筹码"两栏对比、结尾金句卡——这些不是 AI 现场画的，
是设计师提前做好的"版式模板"，就像 PPT 模板一样，风格、配色、动画都定死了。

**第 2 步：AI 往模板里填内容。**
AI 负责决定"哪个位置放什么字、配哪张图"：比如从文案里提炼出"3800"这个数字
放进数字卡、把"美国建议 vs 中国回击"拆成两栏。模板是死的，内容是活的。

**第 3 步：把"网页"录成视频。**
这些模板本质上是**网页代码**（就是做网站用的那种技术）。有个叫 Remotion 的
知名开源工具，专门干"把网页一帧一帧录成视频"这件事，网页里那些动画
（下划线慢慢画出来、图标弹一下、文字依次浮现）都是网页天生就会的。

### 我怎么知道的（两条实锤证据，不是猜的）

1. 我把他们的成片文件用工具拆开，在文件的"出厂信息"里发现一行字：
   **Made with Remotion 4.0.509**——等于在产品上盖了个章。
2. 他们家软件的接口数据里写着渲染模板的文件名：
   **editorial-v1.tsx**——.tsx 就是网页组件代码文件的标准扩展名。

两条证据互相印证，这个结论是确定的。

---

## 二、为什么我之前做的差距那么大

打个比方：**他们是用网页排版软件做海报，我是用 Windows 自带的画图板在拼图。**

内容的位置我能摆对（哪句话配哪张图、卡片放哪里），但网页才能做出的东西我画不出来：
精致的字体渲染、文字依次浮现的动画、下划线一点点画出来的效果、卡片的阴影和质感、
还有那套专业的设计细节（小红条、角标代码、青色下划线这些装饰）。

所以差距不是"我再调调参数"能解决的，是方法本身到了天花板。

---

## 三、我做了什么：照他们的思路重做一遍

既然确认了他们的方法，我就不再修补旧方法，直接换了他们的方法：

1. **装了同款工具 Remotion**（对个人免费、可商用），
   照着参考片把那套模板一个一个用代码复刻了出来：
   片头卡、数字标注卡、事实卡、两栏对比卡、大字观点卡、金句卡……一共十来个组件。
2. **字体**换成思源黑体（免费的重磅字体，字重接近他们的效果）。
3. **保留了我这边本来就达标的部分**：配音合成、多音字修正、镜头和字幕的时间轴、
   背景音乐、开场音效、自动质检。
4. 现在的流程是：我把"填什么字、配什么图、每句话几分几秒"整理成一张内容清单 →
   Remotion 按清单渲染出无声画面 → 再把配音、音乐、音效混进去 → 成片。

这和 Niwo 的内部流程是**同一个架构**。等于说：他们的"印钞机"是什么样的，
我的现在就是什么样的。

# 六、完整流程步骤详解（白话版·逐步对照）

## 第一部分：Niwo 从上传到成片的完整流程

**阶段 A：素材包制作（发生在 ChatGPT/Codex 等 Agent 里，不在他们服务器上）**
1. 用户把材料丢给 Agent（PDF/链接/聊天记录都行）。
2. Agent 读材料 → 写口播文案 → 跟用户确认。
3. Agent 去网上**真实下载**相关图片和视频（不是只给链接）。
4. 用 ffmpeg 把视频裁成 8-12 秒的短镜头。
5. 打包成 zip：content.json（文案）+ manifest.json（素材清单）+ images/ + videos/。

**阶段 B：上传（浏览器里完成，zip 本身不上传）**
6. 浏览器把 zip 在**本地解压**。
7. 调接口创建项目，拿到项目编号。
8. 给每个素材文件要一个"上传许可证"（预签名 URL，本质是阿里云 OSS 云存储）。
9. 把每个文件逐个传上云存储。
10. 提交 content.json + manifest.json 的内容，服务端校验解析，项目状态变"就绪"。

**阶段 C：渲染配置（用户在工作台界面上点选）**
11. 用户选：成片形态（竖屏信息版/竖屏/横屏）、版面（卡片式）、明暗基调（自动/浅/深）、
    配音音色（试听后选）、语速、背景音乐、智能音效档位、字幕开关、资料来源开关、
    免责声明、IP 形象、渲染模型。
12. 点"开始渲染"，按秒数预扣积分（88 秒片扣 45 积分，失败退回）。

**阶段 D：渲染（服务器后台跑，约 8-25 分钟）**
13. 素材准备：从云存储拉全部素材、校验完整性。
14. 分镜规划：AI 把文案拆句，决定每个镜头用哪个素材、镜头多长（实测约 6 秒/镜）。
15. TTS 配音：文字转语音，同时生成**逐字时间戳**（后面字幕按这个对齐）。
16. 画面设计：LLM（gpt-5.6-luna）读文案，决定哪些句子配"设计卡片"（数字标注、
    两栏对比、事实卡……），并**改写出卡片上的文案**（不是照抄原文，是改写成金句）。
17. 画面校验：视觉模型逐镜检查画面和内容是否匹配。
18. 预览帧：生成关键帧预览。
19. 最终合成：**Remotion 把 React 模板（editorial-v1.tsx）渲染成无声视频**
    ——把"网页"一帧一帧录下来，动画、字体、排版全是网页级质感。约 2 分钟。
20. 上传成片：传回云存储，用户拿到下载链接和在线播放。

## 第二部分：我的复刻流程（本地 videogen）

1. 素材包制作：与阶段 A 完全相同（我就是照他们的协议做的），已验证——
   同一份 zip 他们服务端照单全收。
2. 版本自检：跑一次更新检查（对齐他们的协议演进机制）。
3. TTS 配音：edge-tts（微软免费接口）合成配音 + 逐字时间戳；
   多音字用"等长同音字替换法"修正读音（字幕保持原文）。
4. 分镜规划：规则引擎把文案拆句 → 按素材清单里的 script_anchor 配镜头 →
   首镜自动做片头卡、末镜自动做金句卡 → 数字标注卡/两栏对比卡/事实卡选择器
   （中文数字转阿拉伯数字、立场关键词切分）。
5. 设计文案提炼：目前规则提取（**待接入智谱 GLM，key 已配好测通**）。
6. 导出内容清单（props.json）：每个镜头的类型/素材文件/起止毫秒/卡片文案 +
   每句话的字幕时间戳 + 标题带高亮 + 来源 + 免责声明。
7. Remotion 渲染：React 模板（editorial 模板的复刻，十来个卡片组件 + 入场动画编排
   + 思源黑体 Heavy）读清单，headless Chrome 一帧一帧录成无声视觉轨。
8. ffmpeg 混音：配音 + 背景音乐（自动淡出）+ 开场音效（whoosh，hook 档位）。
9. 自动质检：逐镜头抽帧查黑屏/空白、字幕时间轴查错位、音视频流完整性、时长偏差。
10. 输出成片。

# 八、用户实测反馈修复（v7 → v8）

用户看 v7 后点名三个问题，全部定位修复并量化验证：

1. **长字幕溢出面板**（截图实锤："各家别再比赛式地提升模型能力了"的"了"字掉到面板外）
   根因：自适应字号公式写错（系数 1.38 虚涨了允许字号）。
   修复：改为按"中文字=1.0 字宽、英文数字=0.56"实测宽度反推字号（面板内宽 730px）。
   验证：31 字最长句单行放下（31.7px），无换行无溢出。
2. **页脚断行**（"环球时报"被切掉）：同样按实测宽度自适应缩小 + 强制单行。验证：两行各自单行 ✓
3. **图片轮播感**：根因是修"图片不裁切"规格时把运动效果弄丢了（静帧 5-6 秒 = 幻灯片）。
   修复：图片补回 Ken Burns 缓慢推拉（奇偶镜头推/拉方向交替）。验证：同一镜头 2.5 秒间隔 27.5% 像素变化。
4. **音效不适宜**：收敛为最小配置——只留"开场 riser（45% 音量）+ 金句卡低音打点（45%）"，
   中段随机感强的转场/弹出音全部移除；所有真实音效先做响度归一化（loudnorm -21dB）再混音，
   保证压在配音之下。音效样本换成 Mixkit 真实采样（电影级 riser 等 8 个入库）。

另：用户提供的 Pexels / Pixabay 免费 API key 已入库并测试通过（搜索+下载均正常），
下一版素材包的图片/视频将从这两个高质量来源补充采集。

# 十一、clone 模式：逐镜头克隆参考片（本轮终点）

"模仿人家的"的最彻底实现——不再让 LLM 自由发挥，而是**把参考片的剪辑决策表完整逆向出来，按图纸复刻**：

1. **镜头边界**：媒体窗区域 5fps 逐帧差分 → 14 段镜头边界（0/5.0/10.0/15.8/.../77.6/84.4s）
2. **逐段素材识别**：35 个素材解码成帧库，与每段中间帧做灰度 MSE 匹配（+人工目检修正）

# 十三、工作台样品设计语言总结 + 第二模板（portrait 竖屏满版）落地

## 13.1 样品来源

- niwo 官网/工作台里的官方样品成片与海报（editorial 与 portrait 两类并存的成品）；
- 本地保存的 Niwo 官方成片（`AI放缓之争-成片.mp4`）抽帧逐帧比对；
- 结论：**Niwo 不是一套版式，而是两套设计语言**，由"成片形态"开关切换。

## 13.2 两套设计语言对照

| 维度 | A · 竖屏信息版（editorial，已有） | B · 竖屏满版（portrait，本轮新增） |
|------|--------------------------------|--------------------------------|
| 画面 | 纸卡居中 + 方形内嵌媒体窗（778×440） | **素材满屏铺满**（cover），无卡片外框 |
| 大标题 | 卡片内标题带（黑底白字 + 左红条，两行） | 顶部居中 76px 两行，高亮词加**红底块** |
| 遮罩 | 无 | 顶部→中部→底部三段落渐变遮罩保证文字可读 |
| 章节标签 | 卡片角标代码（SIGNAL / 01） | 左上角小红条 + 章节名（28px） |
| 设计卡 | 事实/数据/两栏对比/清单等成套卡型，落在内嵌板 | 半透明暗底 + 红描边浮层卡（label/大数字/对比两栏） |
| 字幕 | 落在内嵌板字幕区（恒定 70px） | 底部居中 62px 大字幕，压在满屏画面上 |
| 页脚 | 卡片底两行灰字 | 画面底部来源 + 免责声明，自动缩字号单行 |

## 13.3 落地实现（format=portrait 全链路）
