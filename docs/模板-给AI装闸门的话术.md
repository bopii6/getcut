# 下次开工第 3 天，把这段话术粘给 AI —— 装闸门（GetCut 复盘配套模具）

> 配套阅读：`复盘-Git弯路清单与工程化建议.md` 弯路 3。这份是"能搬走的模具"，粘完就能用。

## 一、用什么（不用你选，AI 会挑错，所以话术里钉死了）

**一门语言只买它自带的那把尺**，不装新框架：

- Python 后端：自带的 `unittest`（或 `pytest`，二选一，只装这一个）
- 浏览器前端：自带的 `node --test`，加一把白盒尺 `tsc --noEmit`
- Python 白盒尺：`ruff`

你项目现在的形状就是这四把，实测 331 条断言活着（后端 294 + 前端 37），零联网、零起服务。

**三条硬要求**（缺一条就会装出一个摆设）：

1. **一条命令跑完全部**，不是一堆命令让你记；
2. **全离线**：不联网、不起服务、不碰真账号真数据，所以 3 秒跑完、你才愿意天天跑；
3. **必须证明它能红**：故意改坏一处要当场变红，改回变绿。

## 二、话术 A：开工第 3 天，装闸门（整段粘）

```
给我这个项目装一道"出货前的质检门"，要求：

1) 只准用语言自带的测试器：Python 用 unittest，前端用 node --test；
   另加两把静态尺：ruff（Python）、tsc --noEmit（前端）。不装别的框架。
2) 全部离线：不联网、不起服务器、不开浏览器、不读写任何真实账号或生产状态文件，
   需要文件就在临时目录里造假数据。整条命令 10 秒内跑完。
3) 入口只有一个文件 tools/selfcheck.sh：一条命令把四把尺全跑完，
   最后一行打印 "绿/红 + 每把尺跑了几条"。退出码必须真实：任一把红就非 0。
4) 判定不许只看退出码——要解析输出，确认"确实跑过 N 条"。
   import 失败导致 0 条测试也算绿，是我最不能接受的。
5) 加一个 --fail-demo 开关：故意注入一处会红的假代码，让脚本自己变红再还原。
   我要用它证明这台质检机不是装饰。
6) 先写 5 条断言就够，只测"真会死人"的：
   未登录能不能读到别人的东西、账号/状态文件被写坏会不会当空库放行、
   计费与次数上限由谁说了算、核心那条链路端到端能不能出一个能打开的产物。
7) 再加一条 CI：push 和 PR 时跑同一个 selfcheck.sh；
   任何"跳过(SKIP)"在 CI 里必须算失败，跳过不算通过。
8) 最后给我看三样：跑绿的输出、跑 --fail-demo 变红的输出、改回后变绿的输出。
   三张截图/三份日志齐了才算交付。
```

## 三、话术 B：每做完一个功能，让它顺手补一条

```
这个功能做完了。给它补一条离线断言，加进 tests/，并跑一次 tools/selfcheck.sh 给我看结果。
要求这条断言必须"能被改坏"：明确指出删掉源码里哪一句它会变红，
并把这句话写进这个测试文件的注释里。
```

## 四、话术 C：每隔一阵，怀疑它是摆设时（体检 prompt）

```
审计一遍现有闸门，不要加新测试，只回答三个问题：
1) 把源码里每条被闸门保护的修法逐条挑出来，随机抽 5 条故意改坏，
   闸门有没有至少一条变红？把"改坏了但全绿"的清单列给我——那就是假闸门。
2) 有没有测试其实在联网/起服务/读写真实状态文件？这种在 CI 里迟早变成 flaky。
3) 文档、README、CI 里写着的测试条数，和实际跑出来的数字对不对得上？
   对不上就把数字变成由闸门自己核对（跑一遍、把条数写进一个文件、CI 比对）。
```

## 五、你自己怎么验收（一句话，不用懂代码）

跑 `bash tools/selfcheck.sh --fail-demo`。**它红了，闸门就是活的；它绿了，AI 就是糊弄你。**

## 六、只测什么，别贪

只测**昨天真出过事、或者出事就死人的那几件事**。你项目里最值钱的几条都是这么来的：未登录不许给素材、状态文件写坏不许当空库、次数与额度不许认客户端自报的数。反过来，"覆盖率 80%"这种数字一条都不保护你。

顺带一条现场教训：本项目 README 现在写着"前端 29 条 / 后端 184 条"，实测是 **37 条 / 294 条**（2026-09-23）。文档里的数字没人管，就是假话的开始——这正是话术 C 第 3 问要治的东西。
