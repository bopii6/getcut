## 微信小程序方案调研 + 服务端出片链路落地

**调研结论（详见 `docs/小程序方案调研.md`）**
- 现有出片内核是 WebCodecs（`Canvas2D → VideoFrame → VideoEncoder → AudioEncoder → mp4-muxer`），小程序完全没有这套 API，**不能移植只能重建**。
- 三条路：A web-view 套壳（**个人主体直接死**，官方明确"不开放给个人类型账号"，与是否认证无关）；B 端上重建（`wx.createMediaRecorder` 只吃 WebGL canvas，码率上限 3000kbps，1080×1920 每帧搬运 8.3MB，千元机易 OOM）；C 云端渲染（选定）。
- 关键区别：**服务器域名（request/downloadFile）个人主体可以配，业务域名（web-view）不行**。C 方案只走前者，所以个人主体够用。
- 变现：个人主体可开**虚拟支付**（类目须含「工具」，月限额 10 万，Android 抽 1% / iOS 抽 12%）；流量主门槛 2026-10-23 起从 500UV 降到 **100UV**。（我曾误判为"个人主体不能支付、流量主要 1000UV"，已被用户纠正并核实。）

**已实现（`server/` + `miniprogram/`）**
- `server/build-draw.mjs`：esbuild 把 `app/src/lib/draw.ts` 打包成 `server/.build/draw.mjs`（37KB）。绘制层是纯函数，零浏览器 API，只有 `render.ts` 里的编码部分依赖 WebCodecs。
- `server/render.mjs`：配音 → 铺时间轴 → 逐帧画 → **RGBA 直接写 ffmpeg stdin**（不落盘 PNG，省 3GB 磁盘和一次编码）。
- `server/audio.mjs`：ffmpeg 解 mp3 → 移植 `buildTimeline` 的人声铺轨 + BGM 闪避（算法一个数没改），输出 16bit WAV。
- `server/jobs.mjs` + `server/api.mjs`：任务队列（默认串行）+ 6 个接口，`/api/video/:id` 支持 Range。
- `server/selftest.mjs`：像素统计自检（空白帧 / 重复帧 / 中文豆腐块），因为视觉模型不可用改走程序化验证。
- `miniprogram/`：原生小程序两页（粘贴→选风格→轮询→存相册）。

**实测数据（本机，Windows）**
- 20.46s 片 614 帧：全链路 90.2s（含 TTS）。
- 15.19s 片 456 帧：任务式 38.9s。
- 输出 h264 1080×1920 30fps + aac 48k 立体声，音轨与画面严格等长，音量峰值 -2.6dB 未削波。

**踩过的坑**
- `lib/tts.mjs` 原来硬编码 `spawn('python')`，本机 `python` 指向 3.13 但 `edge_tts` 装在 3.12（`py -3` 才是那个）。已改为认 `PYTHON` 环境变量，与 `proxy.mjs` 一致。
- 部署目标机是 **Node v18.20.8**（腾讯云 152.136.119.62，Caddy 反代 `/opt/getcut`），新代码需按 18 兼容；`@napi-rs/canvas` 在 Linux 上要拿到 linux-x64-gnu 预编译包。

**115.190.113.128 现状（实测）**

- 80 上已经跑着完整 Web 端：`GetCut · 浏览器出片`（Vite 构建，`Last-Modified` 2026-11-05 09:35，另一个会话部署的）。
- `/api/health` 返回 `{"ok":true,"plan":true,"tts":true,"ttsConcurrency":8,"runtime":"v18.20.8"}` → 是 `proxy.mjs` 那套，Caddy 反代 `/api/*`。
- 所以**出片服务不能再用 `/api` 前缀**，否则和旧后端撞车。方案：挂 `/v1`。

**为此做的改造**
- `server/api.mjs`：新增 `GETCUT_API_PREFIX`（默认 `/api,/v1`）前缀归一化，路由表只写一套（`/health` `/plan` `/job` `/jobs` `/video/:id`），`stripPrefix()` 剥前缀。
- `server/jobs.mjs`：`publicPrefix()` 取 `GETCUT_API_PREFIX` 第一项生成 `videoPath`，保证「路由前缀」和「返回给客户端的地址」不会自相矛盾。
- `miniprogram/app.js`：`API_BASE`（只到域名/IP）+ `API_PREFIX` 拆成两个；`utils/api.js` 的 `request()` 拼 prefix，`videoUrl()` 不拼（服务端已带）。
- 踩坑：Git Bash（MSYS）会把 `VAR=/v1` 自动转换成 `D:/WorkBuddy/.../v1`，导致 `videoPath` 变成 Windows 路径。Linux 上无此问题，本地调试别在命令行前置赋这种值。

**修掉的真 bug**
- `render.mjs` 帧数差一帧：原来 `totalFrames=round(videoSec*FPS)`，但逐段各算 `round(beat.duration*FPS)`，四舍五入累积误差 → 「计划 337、实画 336」整条失败。改成按累计时间取边界、最后一段强制对齐 `totalFrames`，总和必然相等。

**部署产物（`deploy/`）**
- `package.json`（只依赖 `@napi-rs/canvas`）、`getcut-render.service`（systemd，`GETCUT_API_PREFIX=/v1`）、`install.sh`（六步：Node→ffmpeg→edge-tts→字体→npm→systemd）、`push.sh`（tar over ssh，只传必需 20MB）、`README.md`。
